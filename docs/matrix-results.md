## Triage

Set with `tests/matrix.py --triage ENTRY "text"`.

- **k48ap-7B405**: pass on the first run: catalog entry only.
- **k48ap-7B500**: pass (merged tree 21:05): boot 1's quit was labelled 'helper exited unexpectedly (code 0)' although power-off confirmed in 16 s and the helper exited 0; boot 2 read 'The emulator stopped.' Reason-string race in the new DeviceLink reap path (multidevice a2d4a92), not a boot problem.
- **k48ap-8F190**: (c) iOS 4.3 boots: IOP v3 handshake, VFL/FTL, root, launchd, lockdownd, SpringBoard all come up on the real iBoot chain (qemu-ios dsi-stopstate branch ba740d27^ on ipad1 9a81b9a2ae + this tree). Three emulator findings on the way, each fixed generically: (1) DSIM STATUS bit 8 (StopStateClk) was pinned on; AppleS5L8720X-91's DSI driver snapshots STATUS at start and takes it as 'link down', so the first display-off (auto-lock, the halt) panicked 'enableInterface redundant disable request' (8638f9f095); kboot= additionally starts the link the way iBoot leaves it (85bf5a7ed7); (2) EmbeddedIOP-20 control messages complete with 'done' over the opcode, else 'timed out waiting for workloop to process completed command' at shutdown (d848e1ae47). Keybag one-shot then passes (the 4.3.0 FIL, IOFlashStorage-410.3, has no epoch check; the 'epoch roll wait' is 410.4/4.3.5's, see 8L1). Remaining blocker, class H (the iop-v3 instrument): at shutdown, after the IOP sleep control message, the driver's diagnostic watchdog ping fails to send (kIOReturnNoResources, before any doorbell) and panics 'IOP watchdog: unexpected diagnostic state' (EmbeddedIOP.cpp:929); keeping the HLE awake changes nothing (ba740d2748, reverted), so it is the AP-side state machine around the real firmware's sleep/stop: the IOP core's to answer. Evidence: matrix-results/k48ap-8F190/{seal.log,keybag-1.log,firmwarekit.log}. Also seen: AppleD1815PMU::_readADCGated(3) 'ADC read bad state: 1' x10 during shutdown (PMU ADC mux 3 model gap, harmless so far).
- **k48ap-8G4**: (no keys) 4.3.1: The Apple Wiki has no Restore/Update ramdisk keys, so the data-protection keybag step has no ramdisk to boot (the decryptor skips keyless components with a warning). Would then hit 8F190's IOP panic. Needs the ramdisk keys from another public source or the keybag built another way.
