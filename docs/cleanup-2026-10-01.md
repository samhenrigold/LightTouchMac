# Cleanup and build reuse, 2026-10-01

Changes are isolated in the reuse worktrees. The application remains the GUI; guest compilation and dependency inventory belong to qemu-ios. No hardware model changed in this pass.

The retired 2.x EAGL implementation was removed from the old 1.x/2.x framework source. The retained plain-C front end is now `gles1x.c` / `build-gles1x.sh`; 2.x–5.x continue using `gles-public`. The GLI reader is still needed by 5.x macro contexts and remains. Research engine harnesses and the historical export survey also remain useful. All 41 files from a complete guest export match the previously qualified bundle export byte for byte, including the unsigned 1.x framework and both guest packages. No guest package serial bump is needed for identical payloads.

`contrib/guest-package/build_inputs.py` now owns the component-copy list and source inventory used by the exporter. It fingerprints SDK contents, compiler resource headers, compiler/linker tools, Python and the signer. The exporter compares snapshots before copying and after compilation, rejecting a build whose dependencies changed. Build outputs and generated stubs are excluded. Added/deleted source files are dependencies; modified SDK contents invalidate reuse even with unchanged size and timestamp.

Light Touch validates that shared inventory instead of rejecting every change to emulator HEAD. The original build commit stays in the export receipt. Older manifests retain their strict same-commit requirement. On this host a full export took 10.58 seconds; validation after committing the cleanup took 0.72 seconds and accepted the unchanged guest inputs across the commit. This measures the guest stage only, not a whole release or a cold SDK cache.

Packaging now includes the complete build record in its cache key, so unchanged compiled binaries cannot preserve stale source revisions, pins or guest/native manifests. Verification also checks full source identity. Existing stage state needs one repackage to acquire the new receipt. The current release instructions no longer describe a bundled prepared iPod or the retired GL engines; consecutive stages can share one preflight invocation.

Validation: release unit suite 34/34; dependency inventory tests 4/4; guest loader host contract test; export-name checks for the retained 1.x front end and public framework; shell syntax; complete source-copy guest export and 41-file hash comparison. Native universal packaging and a packaged session are checked separately in the private candidate build. Intel execution, oldest-host testing, Developer ID signing and notarization remain separate release gates.
