## 1. What devos50 built, and where it lives

**It is already in our fork.** `upstream/ipod_touch_1g` = `501c85c4f8` (2023-11-07), identical to GitHub's branch head (GitHub API: sha 501c85c4f8a3…, 2023-11-07). devos50's own 1G commits run 2021-10-01 (`94963a4588 "iPod Touch 1g"`) → 2022-12-24 (`01bdf8560f` machine args, `82fab923c7`/`7385a19248` iBoot + NOR checked in); the last functional ones are `d2236805ff` "Multitouch working!!!" (09-21), `0c313bf18f` buttons (09-22), `beaf938da3` "More work on SDIO/WiFi" (09-25), `a5ac6115bc` scrolling (10-02). After that only a Linux compile fix (2023-01) and a contributor's FPE guard (2023-11). Nothing of it is on `ipad1` (no `hw/arm/ipod_touch.c`; only the `S5L8900_GPIO_IRQS` names survive in `ipod_touch_2g.c:62`). His repos are still alive (`qemu-ios`, `qemu-ios-generate-nand`, `qemu-ios-generate-nor` all pushed 2026-09-26/27) but the 1G branch has not moved.

**Machine** `-M iPod-Touch`: `hw/arm/ipod_touch.c` (678 lines) + 21 model files (~4.6 k lines; `git show upstream/ipod_touch_1g:hw/arm/meson.build:61`). Memory map in `include/hw/arm/ipod_touch.h`.

**Boot chain** (blog pt 1, `ipod_touch.c`): reset PC = `IBOOT_BASE 0x18000000` — the decrypted **iBoot-204 RELEASE** checked in as `data/iboot_204_n45ap.bin` (139,264 B; banner "iBoot-204", "RELEASE"). A bootrom file is loaded at `VROM_MEM_BASE 0x20000000` (the public `bootrom_s5l8900`, 64 KB, GitHub release `n45ap_v1`, 2022-12-24 — blog: a securerom.fun dump "with missing code", hence "execute iBoot instead"). Two bootrom jump-table entries (`0x2000008c`/`0x20000090`) are redirected to stubs at `LLB_BASE 0x22000000` (+0x80 `MOVS R0,#1; BX LR`; +0x100 stores r0 into a "8900 engine" MMIO at `0x3F000000`) so the **8900 decryption of the kernelcache is bypassed**; `ipod_touch_8900_engine.c` is an empty file. NOR = 1 MiB **parallel CFI** flash (`pflash_cfi02_register(NOR_MEM_BASE 0x24000000 …)`, `-pflash data/nor_n45ap.bin`) holding IMG2 images + boot-args, generated by `qemu-ios-generate-nor` (branch `ipod_touch_1g`: `generate_nor.c` 12.6 KB + `aes.c` + a `decryptor` submodule; inputs are the seven `.img2` of 3A101a). Command line (blog pt 2): `qemu-system-arm -M iPod-Touch,bootrom=…,iboot=…,nand=… -serial mon:stdio -cpu max -m 1G -d unimp -pflash nor.bin` (RAM is a fixed 128 MiB at `0x08000000`; `-m` is ignored).

**NAND**: the S5L8900 **FMC** (`ipod_touch_nand.c`, 246 lines: FMCTRL0/1, CMD, FMADDR0/1, FMDNUM, FMFIFO, RSCTRL; 8 banks, 2048+64 B pages, chip ID `0xA514D3AD`), an ECC block at `0x38F00000` that always reports success (77 lines), and the **ADM** NAND-upload DMA at `0x38800000` (276 lines). Store = directory `nand/bank<N>/<page>.page`; reads only plus a minimal `is_writing`. Built by `qemu-ios-generate-nand` (`main` branch, C: `generate_nand.c` + `vfl.h/ftl.h/wmr.h/gpt.h/mbr.h`): BANKS 8, BLOCKS_PER_BANK 4096, PAGES_PER_BLOCK 128, FIL_ID `0x43303032`, "DEVICEINFOBBT" at block 0, VFL context at block 35, FTL context version `0x46560000`, MBR+GPT with **one HFS+ partition** from `filesystem-readonly.img` (no data partition on 1.x).

**Other peripherals**: CLCD at `0x38900000` (same register map as the 2G's; fb at `0x0FE00000`); LCD panel on SPI1 as a 4-command ID stub (`ipod_touch_lcd_panel.c`, 63 lines); **MBX** = a 16 MiB stub returning three IDs, and `LK_ENABLE_MBX2D=0` injected into SpringBoard's launchd plist (no GPU); **touch** = Zephyr on SPI2 (`ipod_touch_multitouch.c`, 418 lines); buttons via GPIO group 3 from host keys; **audio**: the three I2S blocks are allocated as plain RAM, no codec; **USB**: Synopsys OTG at `0x38400000` + PHY at `0x3C400000` modelled, "nonfunctional" (blog); **Wi-Fi**: 105-line SDIO host stub, no card; PMU **PCF50633** at I2C1 addr 0x73 (103 lines); LIS302DL at I2C0 0x1D; AES/SHA1; TVOut ×3 plus a per-build hack MMIO at DRAM `0x8a25960` (`TVOUT_WORKAROUND_MEM_BASE`, a kernel-data address). **Rootfs bake** (`docs/changes.md` in generate-nand): fstab → rw, drop line 2; create `/var/root/Library/{AddressBook,Lockdown,Preferences}` with `AddressBook.sqlitedb`, `data_ark.plist`, `activation_records/pod_record.plist`, `com.apple.springboard.plist`; keep only six LaunchDaemons (AddressBook, CommCenter, configd, lockdown, notifyd, SpringBoard).

**State reached**: iPhone OS **1.1 build 3A101a** (blog says "1.0") boots to the SpringBoard home screen with working multitouch; Calculator/Calendar/Settings navigable. Left because "functionality is limited to some stock apps, not all of which are fully functional" and no App Store (2G post). All inputs are public: `bootrom_s5l8900`, `iboot_204_n45ap.bin`, `nand_n45ap.zip` (162 MB), `nor_n45ap.bin` at github.com/devos50/qemu-ios/releases/tag/n45ap_v1.

## 2. Overlap with our shared models

Most **bases are identical** between S5L8900 and S5L8720 (`ipod_touch.h` vs `ipod_touch_2g.h:112-177`): SHA1 `0x38000000`, DMAC0 `0x38200000`, USB OTG `0x38400000`, CLCD `0x38900000`, NAND `0x38A00000`, AES `0x38C00000`, SDIO `0x38D00000`, VICs `0x38E0x000`, TVOut `0x391-0x393`, MPVD `0x39600000`, DMAC1 `0x39900000`, MBX `0x3B000000`, SPI0/1/2 `0x3C300000/0x3CE00000/0x3D200000`, USB PHY `0x3C400000`, I2C0/1 `0x3C600000/0x3C900000`, I2S `0x3CA00000`, UART0 `0x3CC00000`, SRAM `0x22020000`, DRAM `0x08000000`. **Moved**: CLOCK0/1 (`0x38100000/0x3C500000` vs `0x3C500000/0x3E000000`), TIMER (`0x3E200000` vs `0x3C700000`), WDT (`0x3E300000` vs `0x3C800000`), GPIO (`0x3E400000` vs `0x3CF00000`), CHIPID (`0x3E500000` vs `0x3D100000`), SYSIC (`0x39A00000` vs `0x39700000`), UART1-4 (`0x3CC04000…` vs `0x3DB00000…`), H264 (`0x39800000`; the 2G's `0x38F00000` is the 1G's NAND ECC), VROM (`0x20000000` vs `0x0`), iBoot (`0x18000000` vs `0x0FF00000`). **Absent on the 1G**: MIPI-DSI, SWI, AMC, SPI3/4, FMSS, PKE (not in the 1G map; 1.x iBoot has no RSA), BT, compass. Same IRQ numbers for the shared blocks (timer 7, SPI 9-B, LCD D, DMAC 10/11, I2C 15/16).

## 3. Pipeline for 1.x

IPSW layout (verified on `/Users/shg/Developer/qemu-ios-files/activation-native/iPod1,1_4B1.ipsw`, `unzip -l`): `Restore.plist` only (no BuildManifest; BoardConfig `n45ap`, `RestoreKernelCaches`, `RestoreRamDisks`, `SystemRestoreImages`), `Firmware/all_flash/all_flash.n45ap.production/{LLB,iBoot,DeviceTree,applelogo,recoverymode,needservice,batterycharging,batterylow0,batterylow1}.img2` + `manifest`, `Firmware/dfu/{iBSS,iBEC,WTF}.dfu`, `kernelcache.release.s5l8900xrb`, rootfs `018-3755-1.dmg` + update/restore ramdisks. Containers (in-memory checks): every component is **8900 v1.0 format 0x03** → AES-128-CBC with the public **key 0x837** (`188458A6…`), not the GID (correction to the brief); decrypted kernelcache starts `complzss` (our `LZSS.swift` applies); iBoot's payload is **IMG2** (`2gmI`, type `ibot`, load `0x18000000`). Rootfs is `encrcdsa` v2 — `VFDecrypt.swift` applies as-is; keys public (ipsw.me: 4B1 `c7973558…`, 3A101a `6f021b47…`; all six 1.x builds listed). IMG3 begins at 2.0 (and 2.x IMG3s use the plain-tail convention `FirmwareDecryptor` already detects).

**FirmwareKit lacks**: 8900 and IMG2 parsers (~70 lines Swift; `imgtools/build_nor.py:7-77` already documents the IMG2 superblock for the K48 NOR — reusable knowledge); an `.img2` path table (`BuildIdentity.swift:172-178` hard-codes `.img3` names for the Restore.plist route); `N45NOR` (port `generate_nor.c`) and `N45NAND` (port `generate_nand.c`, 8 banks × 2048 B, single partition; sibling of `N72NAND.swift`); the 1.x `SystemEdits` (changes.md above — not "AppSync", there is no code signing on 1.x); a recipe + `firmware-catalog.json` entries (today only `n72ap`/`k48ap`); a third `DeviceProfile` case (`LightTouchMac/DeviceProfile.swift:11-57`, all ternaries today; only `DeviceSession.swift` and `DeviceProfile+Display.swift` switch on it); a boot-file convention (bootrom + iBoot@0x18000000 + pflash NOR). **Guest tools**: `it_boot`/`it_agent` are armv6, `LEGACY_LINK` (no LC_DYLD_INFO) so 2.x dyld loads them (`contrib/it-boot/build.sh`); 1.x dyld is older, libSystem is Darwin 9.0 — `nm -u contrib/it-agent/it_agent` shows plain BSD/Mach imports plus `_reboot2`, the one symbol to verify on 1.x; `it_boot` needs `/bin/launchctl` and `kern.osversion` (`it_boot.c:102-119`), both present. No AMFI on 1.x, so ldid signatures are moot; no App Store, no IPA format — third-party apps were bare `.app` dirs in `/Applications`. The SpringBoard-side dylibs (`it_typein`, `sblaunch`, `mbxshim`) are ObjC-runtime driven and 1.x SpringBoard differs; expect them to no-op. **Activation**: `tools/activation/compatibility.json` contains an `iPod1,1` / `4B1` case marked `"validation": "experimental-static-only"`; nothing more said.

## 6. Scope and order

**Milestone 1 — iPod1,1 1.1.5 (4B1) to the home screen with touch, from the stock Apple-hosted IPSW** (4B1 = last 1.x, keys known, on disk, in the activation list; 3A101a is the fallback with devos50's known-good NOR/NAND). Three stages, each with its gate:
- M0 (gate: devos50's public images boot on our tree): `hw/arm/ipod_touch_1g.c` on our tree reusing the shared models (SPI `peripheral=` property, timer IRQLATCH property, chipid words, 7-group SYSIC) + ported FMC/ECC/ADM, panel stub, 8900 hook; boot devos50's public images.
- M1 pipeline (gate: the stock 4B1 IPSW prepares and boots): 8900/IMG2, `N45NOR`, `N45NAND` + 1.x SystemEdits (the largest piece), recipe/catalog/DeviceProfile.
- Debug + persistence (gate: a change survives a clean power-off and reboot; unknown: risk (1) below).
Risks, ranked: (1) **NAND writes** — devos50's FMC is read-only in practice; the 1.x FTL programs/erases pages, so the port needs a real program path plus FMSS's overlay (the 2G's hardest area); (2) QEMU API drift 6.2 → 10.0 in the 1G files (mechanical, medium); (3) the per-build `0x8a25960` TVOut hack must become runtime or a real TVOut model (medium); (4) guest agent on 1.x dyld/libSystem (isolable; exclude from M1); (5) 8900 hook assumes iBoot-204's jump-table use (all 1.1.x ship iBoot-204 — low).

**Every 1G build (2.x/3.x)**: mostly the 2G's work. The 2G kernels drive the very same `AppleS5L8900X*` driver family our models were tuned against (`ipod_touch_2g.c:814`, `ipod_touch_aes.c:473`, `ipod_touch_sha1.c:138`), and 2.x/3.x on the 1G use the 2G's chain: `direct-iboot` from public IMG3 keys, boot-args injection, `gid-blobs`, armv6 guest tools, MBX + `MBXGLEngine-<BUILD>` (7E18's OpenGLES is armv6 on both — verify the GLI TSV matches). 1G-only pieces: FMC NAND (the same old VFL/FTL, 1.x → 3.1.3, per generate_nand's WMR/FIL structures — verify on 7E18's flash driver), SPI panel, WM8758 codec stub (2.1.1 on the 2G panicked without I2S hardware, `f2ec3285e4`), and whether the 1G's 2.x+ iBoot needs a PKE (none in the 1G map). Then 5H11 + 7E18 as the first two (gate: each boots to the home screen on the 2G chain), then a catalog row per build as keys are found; 5A347/5F137 need clean IPSWs from elsewhere.

**Recommended order**: (1) M0 port on our tree with devos50's public images; (2) M1 pipeline from stock 4B1; (3) FMC write path/overlay; (4) 2.x/3.x via the 2G chain (5H11, 7E18 first); (5) Marvell Wi-Fi last or never. Log the TVOut address and `LK_ENABLE_MBX2D` as per-build debt per the matrix rule.
