# Smoke: anomalies worked around or unexplained

Sam, 2026-09-28: "I really hope they are treating them as 'this is broken because our emulator has a gap' and not just
'a hurdle to hack around at skin-deep level'. Where there's smoke, there's fire."

Every workaround, instrument, or unexplained anomaly goes here with its fidelity class (see fidelity-ledger.md) and the
fire we suspect behind it. An entry leaves this list only when the cause is modelled faithfully or shown to be
real-hardware behaviour. New entries are added by whoever ships a workaround; none is closed by deleting it.

Closed:
- iPod 1G lockdown sessions (#51): two causes. (a) Host: 1.1's lockdownd speaks SSLv3 only; the bundled OpenSSL 3.6.3 is now built `enable-ssl3 enable-ssl3-method` (scripts/build-static-deps.sh; security level 1+ still refuses SSLv3, and only libimobiledevice's contexts run at 0) and libimobiledevice 1.4.0 carries build-support/patches/libimobiledevice-sslv3-ios1.patch: below ProductVersion 2.0 the session is SSLv3 exactly (min = max), 2.x+ unchanged (TLS1.0 below 10.0, legacy renegotiation as before). No per-record framing was needed. (b) Emulator (R): the OTG model retired a bulk OUT transfer on every host transaction; the core ends one on a short packet (a ZLP too) or when XferSize/PktCnt run out, and PktCnt counts every packet. 1.x's AppleUSBDeviceMux arms 32 KiB and tells a full-packet end from a short one by PktCnt, so a 512-byte mux packet was merged with the next ("expected 512 bytes, received 540", th_seq 6725 vs 6241: 484 TCP bytes lost) and any session whose flight produced a 512-byte packet stalled (qemu-ios `ipod-1g-sigill`). Matrix n45ap-3A101a through the app's own libimobiledevice: lockdown 4.2 s, Activated, AFC 4/4, persist, shutdown 15.1 s x2 -> `experimental`.
